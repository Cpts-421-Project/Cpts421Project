## 2. Idempotent Deployment Seeding Pipeline ([seed_db.py](file:///Users/asafkedar/Documents/WSU/year%204/Semester%202/CPT_S-421/Cpts421Project/code/backend/seed_db.py))
Executed automatically on container boot (`alembic upgrade head && python seed_db.py`):
1. **`execute_sql_file`:** `find_default_sql_file()` prioritizes the canonical 61-artifact [filtered_small.sql](file:///Users/asafkedar/Documents/WSU/year%204/Semester%202/CPT_S-421/Cpts421Project/code/backend/data/filtered_small.sql) and runs it idempotently using `ON CONFLICT`, `WHERE NOT EXISTS`, and `COALESCE` guards (preserving any admin edits on existing records).
2. **`update_legacy_image_urls`:** Rewrites any legacy external Met Museum (`collectionapi.metmuseum.org` / `images.metmuseum.org`) or British Museum URLs in PostgreSQL `images.file_url` to `/api/images/met_<inv>.jpg` or `/api/images/bm_<inv>.jpg`.
3. **`migrate_external_images_to_bucket`:** Uploads bundled local image files (`code/backend/data/images/`) to the configured S3/Tigris/MinIO bucket first (zero external network traffic), falling back to SSRF-validated streaming download only if a local bundle asset does not exist.
4. **`seed_admin_users`:** Upserts admin accounts from `get_default_admins()` with bcrypt-hashed passwords sourced from environment variables or CSPRNG tokens.
5. **`get_database_summary`:** Logs post-seed row counts; orchestrated end-to-end by `run_seeder`.

## 3. Multi-Layer Image URL Normalization
To guarantee no external third-party URLs leak to browser `<img>` tags:
1. **Service Layer ([object_service.py](file:///Users/asafkedar/Documents/WSU/year%204/Semester%202/CPT_S-421/Cpts421Project/code/backend/src/services/object_service.py)):**
   - `create_object` & `update_object` pass all incoming `file_url` strings through `s3_service.ensure_stored_in_bucket`.
   - `_enrich_object_dict` runs `_normalize_image_url` on every returned object.
2. **Schema Serialization Layer ([schemas.py](file:///Users/asafkedar/Documents/WSU/year%204/Semester%202/CPT_S-421/Cpts421Project/code/backend/src/schemas.py)):**
   - `ImageResponse.normalize_file_url` (`@field_validator("file_url", mode="before")`) rewrites legacy Met, British Museum, or internal `http://minio:9000` URLs into `/api/images/<key>` before JSON serialization.

## 5. Admin Predefined Museum Discovery & Import ([museum_discovery_service.py](file:///Users/asafkedar/Documents/WSU/year%204/Semester%202/CPT_S-421/Cpts421Project/code/backend/src/services/museum_discovery_service.py))
- **Predefined Open-Access Museums:** `met` (Met API `v1.1/search` + `v1/objects`), `cma` (Cleveland Museum of Art Open Access API), `aic` (Art Institute of Chicago v1 + IIIF), `vam` (Victoria and Albert Museum API v2 + Framemark IIIF), and `bm` (The British Museum via Wikidata Action API `P195=Q6373|P276=Q6373` + Wikimedia Commons `imageinfo` thumbnails, avoiding Cloudflare-gated `www.britishmuseum.org/api/_search`), defaulting to `0–899 CE` and curated worker/craft keywords.
- **Persistent Saved Keywords (`discovery_keywords`):** Added [models.py](file:///Users/asafkedar/Documents/WSU/year%204/Semester%202/CPT_S-421/Cpts421Project/code/backend/src/models.py) `DiscoveryKeyword` and Alembic revisions `a1b2c3d4e5f8` & `b2c3d4e5f6a9` (seeding all **62** unique worker/craft terms merged from the 8 defaults and `code/backend/datacollection/keywords`). `MuseumDiscoveryService` exposes `get_saved_keywords()`, `add_keyword()` (case-insensitive dedup, capped at `MAX_SAVED_KEYWORDS = 200`), `save_keywords()`, and `delete_keyword()`, wired to `/admin/discovery/keywords` (`GET`/`POST`/`DELETE` 204), `list_museums()`, and `discover()` so added keywords survive sessions and resets.
- **Deduplication & Rejection Suppression (`ExistingArtifactIndex` + `rejected_artifacts`):** Checks normalized `(museum_id, source_record_id)`, `inventory_number`, `external_url`, and fallback `(object_type, present_location, date_display)` via `match_reason()` (`"rejected"`, `"existing"`, or `None`) across DB `objects`, persisted `rejected_artifacts` tombstones (Alembic revision `c3d4e5f6a7b0`, [rejection_service.py](file:///Users/asafkedar/Documents/WSU/year%204/Semester%202/CPT_S-421/Cpts421Project/code/backend/src/services/rejection_service.py)), and within-batch hits. All 5 adapters advance up to `MAX_PAGES_PER_KEYWORD = 3` pages past skipped/rejected records, while offline `data_ingest.py` & `british_museum_ingest.py` also skip rejected tombstones and `review_status == 'rejected'` rows. Admins can reject candidates directly via `POST /admin/discovery/reject` and undo via `DELETE /admin/discovery/rejected/{id}` (HTTP 204), or restore via Review Queue Undo (`PATCH /objects/{id}/review`).
- **Full Field Population & Safe Staging:** Populates all `2_excel` fields (`present_location`, `production_location`, structured cm dimensions including Met `Thickness`/`Length` depth fallback and `kg` `weight`, HTML-stripped descriptions, inscriptions, publications, inferred coordinates, multi-image Chicago citations, `assembled_caption`), caches images into S3 (`""` fallback if storage fails, preserving `INV-SEC-01`), and inserts records with `review_status="pending"` inside per-item savepoints.
